Architecture

From one text to a finished plan, on AWS

Serverless from edge to database: nothing to patch, nothing running when nobody is texting.

03 What happens to one message

  1. Photon delivers the iMessage to our public Function URL as a signed webhook.
  2. The function verifies the HMAC signature (5-minute replay window), acknowledges within milliseconds and drops duplicates.
  3. It hands off to an async copy of itself, so slow work (the model, a long poll wait) never delays Photon. Retries are off, so a flow never runs twice.
  4. The worker thinks: it loads the user and chat history, runs Claude on Bedrock with tools (location, menus, meal log, plan), and queries Aurora for menus.
  5. It answers through Photon: text, poll, Find My request, voice note or rich card, and every friend is reached privately.
  6. EventBridge ticks each minute to move group plans forward (time, then confirm, then place, then card) even while nobody is texting.

04 Deploy: one command, verified

Infrastructure as code

CloudFormation stacks create the function, tables, IAM, schedule and URL. Re-running is safe.

One-command deploy

npm run deploy builds, uploads, and we check the deployed code hash against the build. A self-test checks voice and Bedrock.

Observable

Every step logs to CloudWatch with the user, tool calls and replies, so a problem is traceable in seconds.

Scale and security

Built for 100 users now, and for growth

Every layer scales on demand. The limits below are settings and quotas, not rewrites.

05 Scale

LayerHow it scalesToday

ModelBedrock Claude Haiku 4.5 through a cross-region inference profile.50 requests/min default quota
PlansEventBridge tick moves every active plan forward; plan state is stored per plan.Many plans in parallel
Honest sizing: ~100 active users are comfortable today. The first limit we would meet is the model's requests-per-minute quota, which is a routine increase request. After that come the Aurora ACU cap and Lambda concurrency, both settings.
Growth path: 10x is three settings (Bedrock quota, Aurora ACU cap, reserved Lambda concurrency). 100x adds a queue (SQS) between webhook and worker and caching of menu answers. Each Photon user has their own line, so load also spreads across lines.

06 Security

ConcernWhat we do
Who can call usThe URL is public because Photon can't sign AWS requests, so every delivery is authenticated by Photon's HMAC-SHA256 signature, checked in constant time with a 5-minute replay window. Unsigned requests are rejected.
SecretsPhoton and ElevenLabs keys live in Secrets Manager and are read at runtime; none are in code or the repo.
Least privilegeThe function's IAM role can only touch its own tables, its own database cluster, its own secrets and itself.
Data at restAurora storage is encrypted; the users table has encryption, point-in-time recovery and is retained if the stack is deleted; chat state expires on a TTL.
Food safety + privacyA code-level guard, not the AI, checks allergies and diet, and the bot never calls a dish "safe". In groups, friends see only the merged restrictions needed to pick a place, never anyone's health numbers.
Consent + reliabilityOnly registered, opted-in users can message the bot, and invited friends can reply STOP. Duplicate deliveries are dropped, retries are off, and voice falls back to Polly if ElevenLabs is down.
